# charter — 项目宪法（不可协商原则）

> 契约 §5.4。一次定义、跨 change 稳定；修改须经人工确认。与 `docs/rules/` 其他规则冲突时以本文件为准。

## 质量底线

1. **未验证不得声称通过**：verify.md 无证据的"完成"一律无效；
2. **不依赖生成器自证**：校验器独立于 init/adopt 实现，结构合规以 validate 为准；
3. **零第三方依赖**：工具链仅用 Node.js 标准库（消费项目侧无运行时依赖）。

## 技术禁区

4. **禁止在项目内复制标准树**（红线 1）：规范引用标准库，不做厚副本；
5. **禁止新增平行 SSOT**：同一事实只有一个权威位置（§7 文件职责表）；
6. **禁止无契约的目录创新**：新结构先改契约，后落模板与校验。

## 协作纪律

7. **保守默认**：工具不删改用户内容；存在即跳过并报告冲突；
8. **契约修改走 spec → plan → 分 Phase 实施**，产物落 `docs/superpowers/`；
9. **每个变更留痕**：change 单元 + 归档 + knowledge 变更记录，链可反查。
