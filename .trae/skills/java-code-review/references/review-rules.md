# 审核规则（RV）v1.0

> 版本 1.0 · 2026-10-30 · 冻结于评审修订后 · 母版 · RV 全部为必检

## 生效规则集构建（执行步骤 2 必做）

`生效规则集 = 母版全集 − 被覆盖规则 + 覆盖层新增条款`

覆盖语义（不得歧义）：

| 情形 | 处理 |
|---|---|
| 覆盖层明确替代某条母版规则 | 该母版条款**不再作为独立判定依据**，改用项目条款判定 |
| 覆盖层新增条款 | 与母版规则**同时生效**，可叠加命中 |
| 覆盖层未声明的规则 | 继续使用母版 |
| 覆盖层以模糊描述暗示豁免 | 不成立；不允许默认豁免母版规则 |

报告首部必须打印四项：已启用必检规则、已启用选检规则、被覆盖规则（须写明母版 ID、项目条款位置、替代关系）、覆盖层缺失情况（缺失则标注「无项目覆盖层」）。

## 问题状态判定

不得把所有未满足条件的情况都定义为误报，必须区分三种状态：

| 状态 | 判定 |
|---|---|
| 确认问题 | 规则违反成立，且有触发路径与证据 |
| 待确认 | 有风险线索，但缺少完整调用链、运行条件或项目约束，无法完成判定 |
| 误报 | 已有证据证明不违反规则，或属于项目明确允许的范式 |

判定为「确认问题」需同时满足：

1. 代码中实际成立，且能给出具体触发路径
2. 违反某条已登记的 ST/TX/RV 规则编号
3. 不属于项目覆盖层明确视为合规的范式

**「无法证明」不等于「证明不存在」**：证据不足只能判为待确认，不得判为误报，也不得直接下缺陷结论。

## RV-01 先声明范围

审核开始前必须写明：范围（方法/文件/模块/change）、基线、不审内容。

基线必须可识别：给出 SVN revision，或注明「工作副本（未提交改动）」并说明工作副本状态。

## RV-02 行号级证据

每条问题必须给行号区间与触发条件，行号以**审核时实际读取的新版本文件**为准。

无法取得稳定行号时，该条列为「待确认」，不进入正式问题清单。

## RV-03 分级标准

分级必须结合业务影响与触发条件判定，**不以违反规则的数量或代码行数决定**。

| 分级 | 判定 |
|---|---|
| Blocker | 必然导致数据错误、资金/账户状态错误或生产不可用，且无人工兜底 |
| Critical | 明确触发条件下导致功能失效或数据不一致 |
| Major | 违反事务/异常/职责边界规则，存在潜在不一致或显著维护风险 |
| Minor | 可读性、复杂度、重复代码等不影响正确性的问题 |
| Info | 文档与实现偏差、口径待确认、优化建议 |

## RV-04 双路交叉验证

派 2 个独立子代理复核候选项，各自返回 `{issue_id, exists, severity, reasoning}`。

| 结果 | 处理 |
|---|---|
| 2/2 | 高置信度 |
| 1/2 | 存在分歧，标注「需人工确认」，并保留双方原始证据 |
| 0/2 | 重新检查候选项；若主审核证据仍成立，**不得仅因子代理未命中而自动删除**，须写明证据与分歧 |

双路验证结果是**置信度信息**，不是严重级别的唯一依据。Blocker / Critical 必须由实际影响、明确触发路径、影响证据及业务后果决定；一个明确的 SQL 状态条件或异常路径证据，不因第二个代理漏看而失效。

同时须防止子代理共享同一错误假设，分歧时回到源码复核。

## RV-05 六维覆盖

| 维度 | 主要规则 |
|---|---|
| 职责与结构 | ST-01～ST-05、ST-08～ST-10 |
| 事务一致性 | TX-01～TX-04、TX-08（含 TX-10 自调用导致事务失效） |
| 异常语义 | TX-07、项目异常规范 |
| 并发幂等 | TX-05、TX-06、TX-09 |
| 可测试性 | ST-07，并结合依赖隔离与现有测试条件（ST-07 只覆盖外部 IO 与时间/随机数依赖的可替换性，不等于完整可测试性） |
| 兼容性 | 接口签名、返回值结构、数据库语义、调用方兼容性 |

每个维度必须给出明确结论，且区分两种表述：

- **无问题**：已完成检查，有证据支持
- **未覆盖**：缺少源码、依赖、测试环境或调用链，无法完成检查，并说明原因

**不允许把「未覆盖」写成「无问题」。**

## RV-06 建议与回退

建议必须是最小改动，并给出回退粒度（哪些文件 revert 可完全撤销）。

回退粒度以实际变更文件为准；只做审核未修改文件时写「无需回退，未修改文件」。

## RV-07 未验证不得声称通过

必须区分静态代码审核、编译、单元测试、集成测试四类证据，不得用静态检查结果代替运行验证。

引用实际命令与输出摘要；未执行的项目明确写「未执行」，不得用推测替代证据。

## RV-08 项目优先并记录偏差

项目规则与母版冲突时按项目规则判定，并在报告末尾单列「与母版偏差」。偏差表固定五列：`| 规则ID | 母版条款 | 项目条款 | 判定依据 | 结论 |`。

## 输出契约补充

- 一个问题可关联多条规则，但必须指定**一个主要规则 ID** 用于统计，其余作为关联规则列出，避免重复计数
- 同一违反事实不得拆成多条问题重复统计
- 范围外问题只记录确实影响当前审核结论的内容；纯优化想法不进入正式报告
