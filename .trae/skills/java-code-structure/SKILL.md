# Java Code Structure

## 适用

- 单个方法超过 50 有效行或嵌套超过 3 层
- 一个方法同时做校验、决策、持久化、远程调用、事件发布
- 需要评估是否该拆分、如何拆分而不改变行为
- 新增 service / 编排类时确认职责边界

## 不适用

- 纯粹的命名与格式规范（见 `docs/rules/detail/java-conventions.md`）
- 事务边界与一致性（用 `java-transaction-management`）
- 完整审核与分级报告（用 `java-code-review`）

## 规则优先级

1. `docs/rules/charter.md`
2. 项目覆盖层 `docs/rules/detail/java-structure.md`
3. 本 skill 的 `references/structure-rules.md`

冲突时以高优先级为准，并在结论中记录偏差。

## 执行步骤

1. 读取项目覆盖层 `docs/rules/detail/java-structure.md`（不存在则跳过并说明）
2. 读取目标方法/类完整源码与其调用方、被调用方，确认职责链
3. 按 `references/structure-rules.md` 的「模块识别」表判定对象所属模块（svc / dao / ctl / lsn）
4. 构建本次启用规则集：该模块的必检规则 + 显式点名的选检规则，**在报告首部逐条列出启用的规则 ID 与未启用的选检规则**
5. 逐条判定启用规则，只报命中项，不逐条罗列未命中项；ST-02 只作为触发证据，违规结论须落到 ST-01 / ST-04 / ST-08
6. 每条命中给 `文件:行号` 证据 + 触发条件 + 影响
7. 给出最小改动建议：先说明「保持行为的拆分边界」，再给方法命名与职责
8. 明确回退方式（按 SVN revert 粒度的文件清单）

## 输出格式

报告首部：

```
审核对象：<文件:行号>
模块：svc
启用规则：ST-01, ST-02, ST-04, ST-06, ST-07（必检）+ ST-09（选检，已点名）
未启用的选检规则：ST-03, ST-05, ST-08, ST-10
```

问题表：

| 规则 ID | 分级 | 证据（文件:行号） | 问题 | 最小改动建议 |
|---|---|---|---|---|
| ST-01 | Major | `XxxServiceImpl.java:120-320` | 单方法混合流程编排与具体业务动作 | 按行为边界拆分为编排入口 + 责任方法 |
| ST-04 | Major | `XxxServiceImpl.java:150-160` | 入口方法直接写 SQL 并发布事件 | 下沉到迁移组件，事件移到提交后 |

ST-01 与 ST-04 可同时命中，但必须在「问题」列分别写明不同的违反事实，不得合并计数为同一问题。

## 约束

- 不直接大规模重构；拆分方案必须先经用户确认
- 拆分不得改变业务行为、接口签名与数据库操作语义
- 不得引入新框架或工具类库来解决结构问题
- 本 skill 只判断代码结构，不判断事务可靠性、异常语义与并发一致性（由 `java-transaction-management` 负责），不产出完整分级审核报告（由 `java-code-review` 汇总两者结果）
