# 质量门槛清单

## G0 准备
- [ ] 仓库根目录、HEAD、分支和工作区状态已记录
- [ ] 既有 Wiki 和用户改动未被覆盖
- [ ] 扫描边界与允许修改范围明确

## G1 Recon
- [ ] 技术栈每项有文件行号
- [ ] HTTP、定时任务、MQ 消费者、CLI、Webhook、事件等**分类**扫描（每类独立清单）
- [ ] 每类入口有扫描范围；未发现时列出已检查路径
- [ ] 配置只记录键名，不泄漏秘密
- [ ] 扫描命令、排除规则、`source_commit`、盲区已记录
- [ ] 抽查至少 10 条证据位置准确

## G2 能力地图
- [ ] HTTP 原始清单逐项存在；`method`/`path`/`handler`/注册位置齐全
- [ ] `http_unique = http_classified + http_unclassified`（即 N_unique = M + U）
- [ ] 计数口径说明重复注册、版本别名、参数化路径、动态路由
- [ ] 非 HTTP 入口**独立表**与独立计数，未混入 HTTP 数
- [ ] 数字已写入 `_manifest.yaml` 的 `entry_counts`
- [ ] 未分类项与动态路由盲区明确

## G3 领域文档
- [ ] 每个领域有入口到存储/外部调用的调用链
- [ ] 关键规则、权限、事务、状态转换有证据
- [ ] 数据字段和索引来自 DDL/schema/model
- [ ] 图表的关键箭头有证据
- [ ] 每域待确认项和检查范围齐全
- [ ] 未把测试或注释当作生产行为的唯一证据

## G4 横切文档
- [ ] 架构结论有源码/配置证据
- [ ] ER 区分物理 FK、应用逻辑关联和推断
- [ ] 状态机说明完整/部分状态
- [ ] 跨域流程只画有证据的步骤
- [ ] 第三方依赖区分声明、初始化和实际调用

## G5 索引
- [ ] README 中列出的文件均存在
- [ ] 业务域→代码路径反查表完成
- [ ] Markdown 相对链接与 Wiki→源码链接有效
- [ ] 孤立文件有报告
- [ ] pending 问题稳定 ID、去重且保留来源
- [ ] `_manifest.yaml` 已更新：`source_commit`、`analyzed_at`、`coverage_status`、`pending_count`、`entry_counts`

## G6 独立审计
- [ ] 至少 20 条；若可审计结论不足 20 条则全部审计
- [ ] 高风险规则、状态机、数据模型和权限均有抽样
- [ ] 审计者独立回源码定位
- [ ] 判定为「错误」的项已修订文档并**再次审计复核**，或标为阻塞
- [ ] 覆盖性与链接检查完成
- [ ] 最终结论为 `通过` / `有条件通过` / `不通过`，且与 `_manifest.audit_status` 一致

## Final（`07-finalize.md` 交付收尾）
- [ ] 无允许范围外文件改动
- [ ] 无秘密值或生产个人数据进入 Wiki
- [ ] `source_commit` 与 `analyzed_at` 在各文档与 `_manifest.yaml` 中齐全
- [ ] 入口计数、pending 数、审计统计在 manifest、能力地图、审计报告间一致
- [ ] 各阶段状态无未解决的 `阻塞`；交付报告区分通过项、有条件通过项、阻塞项与局限
- [ ] 未将「文件已生成」等同于「分析完成」
