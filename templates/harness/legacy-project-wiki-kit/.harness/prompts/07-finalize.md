# 交付收尾 — 完整性、变更边界与交付报告

> **非独立阶段编号**。本 Prompt 在**阶段 6 审计通过或标记为有条件通过**后，由**协调 Agent**执行。  
> 对应质量门槛 `quality-gates.md` 的 **Final** 节；不写入 `STATUS.md` 的阶段表，但在交付报告中记录结果。

不要重新分析所有源码，重点做机械化与交付核验。

检查：
1. `git status --short`、HEAD commit；确认没有修改允许范围外的文件。
2. 检查所有 Wiki Markdown 相对链接是否指向存在文件；代码链接行号仍能定位。
3. 检查所有结论标记、来源、commit/date metadata；查找没有证据锚点的断言。
4. 核对 endpoint 计数等公式、未分类项、非 HTTP 入口、pending 数量和审计样本数量。
5. 检查敏感信息：禁止秘密值、token、私钥、个人/生产数据出现在 Wiki。
6. 核对 `README.md`、`_pending.md`、`_audit.md` 与领域文档是否一致。
7. 明确标注哪些阶段通过、部分通过、阻塞；不要把“文件已生成”等同于“分析完成”。

最终回复只报告：
- 基线 commit 和核对 commit
- 创建/修改的文件
- 各阶段验收结果与证据
- endpoint/其他入口覆盖计数及计数口径
- 领域数量、跨域流程数量、待确认数量、审计样本数与错误数
- 未覆盖范围、无法验证项、需要业务方确认的高优先级问题
- 是否修改源码（应为否）
不得宣称不存在遗漏；说明剩余风险。
