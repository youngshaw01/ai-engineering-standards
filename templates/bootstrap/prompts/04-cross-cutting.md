# 阶段 4 — 横切架构、数据、状态机、跨域流程和集成

输入：通过门槛的 Recon、能力地图、全部领域文档。
输出：
- `docs/knowledge/02-architecture.md`
- `docs/knowledge/data/er.md`
- `docs/knowledge/data/state-machines.md`
- `docs/knowledge/flows/*.md`
- `docs/knowledge/integrations/third-party.md`

规则：只汇总领域文档和源码证据支持的事实。跨域推断标 `[推断]`；证据不足列入待确认。不要为了符合模板虚构事务、缓存、部署组件或外部服务。

A. `02-architecture.md` 覆盖：
1. 系统边界、进程/服务与启动关系。
2. 认证、身份、授权模型；区分“认证成功”与“有权执行”。
3. 错误处理、错误码与异常映射。
4. 事务边界、锁、幂等、重试、补偿和最终一致性。
5. 缓存策略、key、TTL、失效点；若未发现，说明搜索范围。
6. 日志、指标、trace/correlation ID 与告警。
7. 配置与 feature flag。
8. 部署拓扑：仅根据 Docker/CI/K8s/脚本/文档证据；部署文档过时风险需注明。
每节均包含结论、证据、推断/待确认。

B. `data/er.md`：
- 汇总所有领域实体、表/集合、主键、外键、逻辑关联、唯一约束和关键索引。
- Mermaid ER 图只画已证实的关系；逻辑关联用虚线或明确标“逻辑关联/推断”。
- 记录每张表的 DDL/迁移/模型来源与各领域读写者。
- 区分物理 FK、应用层关联、仅名称相似的字段。

C. `data/state-machines.md`：
- 汇总每个领域状态机、状态值定义、触发条件、执行者、失败/重试/超时路径。
- 状态名来自 enum/schema/常量/代码；不要把 UI 文案当数据库状态。
- 标记状态机是否完整，列出无法解释的状态与非法转换处理。

D. `flows/*.md`：
- 仅选择有跨域证据的端到端流程；每个流程一份文件。
- 包含触发入口、主要步骤、调用链、数据写入、事件/外部调用、失败与补偿。
- Mermaid sequence diagram 的每个关键箭头都应在图后有源码证据表。
- 不根据产品常识补全缺失步骤。

E. `integrations/third-party.md`：
- 区分依赖声明、客户端初始化、实际调用、生产/消费。
- 记录服务名称、用途（有证据时）、配置键名、调用位置、超时/重试/错误处理、数据出境/敏感数据风险（仅有证据才断言）。
- 不输出 secret、token、私有地址中的敏感部分。

结束时更新 `STATUS.md`，列出产物、覆盖缺口和待确认项。验收：跨域关系可回溯；图表与证据一致；无无证据连线。每份产物文档尾部加 `## 变更记录` 小节，初始行来源记 `bootstrap`。
