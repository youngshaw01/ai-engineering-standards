# 阶段 1 — 全局侦察（只收集事实）

角色：遗留系统侦察专家。先读 `STATUS.md` 与 `AGENTS.md`。本阶段禁止写业务域文档，禁止修改源码。

输出：`docs/knowledge/00-recon.md`

必须覆盖：
1. 技术栈：语言及可验证版本、框架、构建工具、ORM、数据库、缓存、消息系统、调度器、测试框架。每项附文件:行号；版本未知时写未知。
2. 仓库目录树（深度 2–3）：目录用途只能写“名称显示/配置显示的可能用途 [推断]”，不能当业务事实。
3. 所有入口类别：HTTP/gRPC/GraphQL 路由；main/CLI/worker；cron/定时任务；MQ producer/consumer；webhook；事件监听；启动脚本；管理命令。记录注册位置、method/path/topic/job、handler/函数、调用入口。
4. 配置：配置文件、环境变量读取点、feature flags、服务地址配置。只记录变量名和用途，不输出秘密值。
5. 数据存储：迁移/DDL、模型定义、数据库初始化、索引定义；缓存 key、MQ topic 仅记录有证据者。
6. 外部依赖：SDK/import/客户端初始化和实际调用点分开列出；仅出现依赖不代表实际调用。
7. 规模热点：代码行数 Top 20（明确统计命令和排除规则，如 vendor、生成代码、lockfile）；入口文件和复杂/高耦合热点。
8. 测试、CI/CD、Docker、K8s、部署清单（如存在）。
9. 覆盖说明：扫描命令、纳入/排除路径、未解析动态注册、生成代码、子模块和外部服务限制。

方法：
- 先从构建清单和顶层目录开始；再使用语言/框架适配的搜索方法。
- HTTP endpoint 必须从路由注册点追到 handler；如果框架通过自动发现/注解/生成代码注册，说明发现方法。
- 对每类入口给出可复核清单，不得只写“存在 REST API”。
- 所有关键事实写精确路径和行号。Markdown 链接可用 `相对路径#Lx-Ly`。
- 不确定业务含义统一标 `[待确认]`；推测标 `[推断]` 并写依据。
- 如果扫描量太大，按目录分批，但必须记录已完成与未完成范围，不得把部分扫描写成全量。

## 入口计数（写入 Recon，阶段 2 复核）

对每类入口分别统计并记录扫描范围；**禁止**将非 HTTP 入口计入 HTTP 数：

| 类别 | 本节子标题 | 最少字段 |
|------|------------|----------|
| HTTP/API | `### HTTP/API` | N、N_unique（若可去重）、去重规则、动态路由盲区 |
| 定时任务 | `### 定时任务` | job 名、注册位置、handler |
| MQ/事件 | `### 消息与事件` | topic/queue、consumer/producer、handler |
| CLI/启动 | `### CLI/进程启动` | 命令、入口函数 |
| Webhook/其他 | `### Webhook/其他` | 触发源、handler |

在 `## 元信息与扫描方法` 中写入 `source_commit`（当前 HEAD SHA）。

验收门槛：
- 抽查至少 10 条关键事实，行号与内容对应。
- 每类入口明确扫描范围；没有发现时说明检查过哪些路径。
- 记录扫描总数、排除规则、盲区和 commit SHA。
- 不能通过时标阻塞，不得进入阶段 2。
